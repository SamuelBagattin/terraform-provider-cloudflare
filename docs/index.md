# Cloudflare Provider

The Cloudflare provider is used to interact with resources supported by
Cloudflare. The provider needs to be configured with the proper credentials
before it can be used.

## Getting Started

Try the [getting started tutorial](https://developers.cloudflare.com/terraform/tutorial/)
on [developers.cloudflare.com](https://developers.cloudflare.com). In the walk
through, you will setup Terraform and learn to manage Cloudflare resources such
as DNS records, zone settings, load balancers and much more!

## Example Usage

```terraform
terraform {
  required_providers {
    cloudflare = {
      source  = "cloudflare/cloudflare"
      version = "~> 5"
    }
  }
}

provider "cloudflare" {
  api_token = var.cloudflare_api_token
}

# Create a DNS record
resource "cloudflare_dns_record" "www" {
  # ...
}
```

## Authenticating with wrangler (local use)

On a workstation where you already use
[wrangler](https://developers.cloudflare.com/workers/wrangler/), the provider
can reuse the OAuth session of `wrangler login` instead of an API token:

```terraform
# Local workstation only: reuse the OAuth session of `wrangler login`.
# In CI, use an API token instead.
provider "cloudflare" {
  use_wrangler_auth = true

  # Optional. Defaults to "wrangler"; any command that runs wrangler >= 4.57.0.
  wrangler_command = "npx wrangler"

  # Optional. A profile created with `wrangler auth create work`
  # (needs wrangler >= 4.159.0).
  wrangler_profile = "work"
}

# Resources outside wrangler's OAuth scopes (DNS records, zone settings,
# Zero Trust, ...) need an API token: give them a second provider alias.
provider "cloudflare" {
  alias     = "api_token"
  api_token = var.cloudflare_api_token
}
```

The provider runs `wrangler auth token --json` (wrangler 4.57.0 or later) and
sends the OAuth token it prints. It never reads wrangler's credential files
itself: wrangler keeps storing the session (in a file or in the OS keyring)
and refreshing it.

- **Log in first.** Run `wrangler login` (or `npx wrangler login`). If there is
  no session, or wrangler cannot refresh it, `terraform plan` stops and tells
  you to log in again. The provider never starts an interactive login.
- **Profiles.** `wrangler_profile` selects a profile created with
  `wrangler auth create <name>`, and needs wrangler 4.159.0 or later. It is
  passed to wrangler as `CLOUDFLARE_AUTH_PROFILE`. Without it, wrangler uses
  `CLOUDFLARE_AUTH_PROFILE` from your environment, then the profile bound to
  Terraform's working directory with `wrangler auth activate`, then the
  default login.
- **Scopes.** The token only has wrangler's OAuth scopes (Workers, KV, D1,
  Pages, Queues, read access to zones and a few more; run
  `wrangler login --scopes-list` to see them). Resources outside them, such as
  DNS records, zone settings or Zero Trust, fail with HTTP 403 errors. Manage
  them with an API token, for example through a second provider alias.
- **Local use only.** In CI, use an
  [API token](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/)
  (`api_token` or `CLOUDFLARE_API_TOKEN`).
- **One credential.** `use_wrangler_auth` cannot be combined with `api_token`,
  `api_key`, `email` or `api_user_service_key`. The `CLOUDFLARE_API_TOKEN`,
  `CLOUDFLARE_API_KEY`, `CLOUDFLARE_EMAIL` and `CLOUDFLARE_API_USER_SERVICE_KEY`
  environment variables are ignored with a warning, and removed from wrangler's
  environment so that wrangler returns its OAuth token. Origin CA certificates,
  which need `api_user_service_key`, require a separate provider alias.

The token is kept in memory for 5 minutes (`CLOUDFLARE_WRANGLER_TOKEN_TTL`, a
duration such as `2m`). When the API answers 401, the provider asks wrangler
again and replays the request once. Each wrangler run may take up to 30 seconds
(`CLOUDFLARE_WRANGLER_TIMEOUT`); the first `npx wrangler` run can need longer
if npx has to download wrangler. Concurrent requests share a single wrangler
run, and provider processes running at the same time (for example several
provider aliases) take turns through the lock file
`terraform-provider-cloudflare/wrangler-auth.lock` in the user cache directory,
so that two refreshes never use the same refresh token. A wrangler command you
run yourself at the same moment is not covered by this lock.

## Schema

### Optional

- `api_key` (String, Sensitive) The API key for operations. Alternatively, can be configured using the `CLOUDFLARE_API_KEY` environment variable. API keys are [now considered legacy by Cloudflare](https://developers.cloudflare.com/fundamentals/api/get-started/keys/#limitations), API tokens should be used instead. Must provide only one of `api_key`, `api_token`, `api_user_service_key`.
- `api_token` (String, Sensitive) The API Token for operations. Alternatively, can be configured using the `CLOUDFLARE_API_TOKEN` environment variable. Must provide only one of `api_key`, `api_token`, `api_user_service_key`.
- `api_user_service_key` (String, Sensitive) A special Cloudflare API key good for a restricted set of endpoints. Alternatively, can be configured using the `CLOUDFLARE_API_USER_SERVICE_KEY` environment variable. Must provide only one of `api_key`, `api_token`, `api_user_service_key`.
- `base_url` (String) Value to override the default HTTP client base URL. Alternatively, can be configured using the `base_url` environment variable.
- `email` (String) A registered Cloudflare email address. Alternatively, can be configured using the `CLOUDFLARE_EMAIL` environment variable. Required when using `api_key`. Conflicts with `api_token`.
- `use_wrangler_auth` (Boolean) Authenticate with the OAuth session of `wrangler login` instead of an API token. The provider gets the token from `wrangler auth token --json` (wrangler >= 4.57.0) and asks again when it expires. Meant for local workstations; use API tokens in CI. Wrangler's OAuth scopes are limited, so resources outside them fail with 403 errors. Conflicts with `api_token`, `api_key`, `email` and `api_user_service_key`; their environment variables are ignored. Alternatively, can be configured using the `CLOUDFLARE_USE_WRANGLER_AUTH` environment variable.
- `user_agent_operator_suffix` (String) A value to append to the HTTP User Agent for all API calls. This value is not something most users need to modify however, if you are using a non-standard provider or operator configuration, this is recommended to assist in uniquely identifying your traffic. **Setting this value will remove the Terraform version from the HTTP User Agent string and may have unintended consequences**. Alternatively, can be configured using the `CLOUDFLARE_USER_AGENT_OPERATOR_SUFFIX` environment variable.
- `wrangler_command` (String) Command that runs wrangler when `use_wrangler_auth` is enabled, for example `npx wrangler`. It is split on spaces (quotes group words) and is not run through a shell. Defaults to `wrangler`. Alternatively, can be configured using the `CLOUDFLARE_WRANGLER_COMMAND` environment variable.
- `wrangler_profile` (String) Wrangler auth profile (created with `wrangler auth create`) to take the OAuth token from, passed to wrangler as `CLOUDFLARE_AUTH_PROFILE`. Requires wrangler >= 4.159.0. When unset, wrangler uses `CLOUDFLARE_AUTH_PROFILE` from the environment, then the profile bound to the working directory with `wrangler auth activate`, then the default login.
